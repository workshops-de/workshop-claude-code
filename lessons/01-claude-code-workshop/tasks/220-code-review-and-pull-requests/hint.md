<details>
<summary>💡 Hint 1: Review the feature, not only the lines</summary>

A diff shows what changed, not how the feature is used. Ask what the feature does, who uses
it, and what could go wrong, then check the code against your answers.

</details>

<details>
<summary>💡 Hint 2: Findings are input, not verdicts</summary>

Both reviewers can be confidently wrong. For each finding, ask Claude for the exact input or
request that triggers it. If nobody can show one, it's "discuss", not "real".

</details>

<details>
<summary>💡 Hint 3: Green tests prove what they test</summary>

Read the tests in the PR as part of the review. Which cases do they cover, and which would you
add before approving?

</details>
