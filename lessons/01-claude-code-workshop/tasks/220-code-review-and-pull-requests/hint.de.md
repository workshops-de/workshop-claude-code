<details>
<summary>💡 Tipp 1: Das Feature reviewen, nicht nur die Zeilen</summary>

Ein Diff zeigt, was sich geändert hat, nicht, wie das Feature genutzt wird. Fragt, was das Feature
tut, wer es nutzt und was schiefgehen könnte, und prüft dann den Code gegen eure Antworten.

</details>

<details>
<summary>💡 Tipp 2: Findings sind Input, keine Urteile</summary>

Beide Reviewer können selbstsicher falsch liegen. Fragt Claude bei jedem Finding nach der exakten
Eingabe oder Anfrage, die es auslöst. Wenn niemand eine zeigen kann, ist es „diskutieren“, nicht
„echt“.

</details>

<details>
<summary>💡 Tipp 3: Grüne Tests belegen nur, was sie testen</summary>

Lest die Tests im PR als Teil des Reviews. Welche Fälle decken sie ab, und welche würdet ihr vor
der Freigabe ergänzen?

</details>
